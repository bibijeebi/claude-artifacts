01 Concept

What we're actually building.

A rhythm game where notes scroll down 7 lanes, each lane mapped to one of the guqin's open strings. When a note hits the strike zone, Bekah plucks that string on her real guqin. A microphone listens, identifies which string was plucked and when, and scores the hit. No buttons, no plastic guitar, no MIDI cable — she plays her actual instrument.

▸ PLAY ENVIRONMENT

Why this works for guqin specifically: it's a monophonic, plucked, slow-attack instrument with widely-spaced fundamental pitches. Every property that makes pitch detection hard for piano or guitar (polyphony, sustain overlap, narrow intervals) is absent here. The guqin is basically the easiest stringed instrument on earth for a computer to listen to.

▸ ANGLE

This doubles as a practice tool, not just a game. Beginner guqin is brutal because traditional notation (jianzipu, 减字谱) is opaque and there are almost no English tutorials. A 7-lane chart is dead-simple visual notation that lets her learn songs by sight-reading falling notes the way millions of kids learned guitar from Guitar Hero.

02 The instrument as a machine input

Bekah's Fu Xi style guqin from Sound of Mountain Music, restated in engineering terms.

Standard tuning is zhengdiao (正调): a pentatonic scale across two octaves. The 7 open strings are well-separated in frequency, which is the whole reason this project is feasible.

The minimum gap between adjacent strings is ~12% (a whole tone). Human just-noticeable-difference for pitch is ~0.5%. A YIN or autocorrelation pitch tracker has roughly an order of magnitude more discrimination than we need.

▸ COMPLICATION

Guqin technique includes three sound types: open plucks (sanyin, 散音), pressed notes (anyin, 按音, left hand on string), and harmonics (fanyin, 泛音, light touch over the 13 hui markers). MVP only handles open plucks. Pressed and harmonic notes are V2 — they require detecting arbitrary pitches between strings, which crepe/SPICE handles but adds chart complexity.

04 Input detection — piezo per string

The hard part, solved by hardware instead of signal processing voodoo.

What we tried first, and why it didn't survive contact

Original plan: single USB mic + YIN pitch detection. Benchmarked it. Result: passable for sustained tones but fails on real eighth-note playing. The guqin's defining acoustic feature — strings that ring for 5+ seconds — means consecutive plucks overlap in the air. Pitch trackers see the overlap as noise and either misclassify the new note or lock onto the previous one. By note 8 of a 120 BPM run, cumulative timing error was ~700ms. The same issue plagues Rocksmith's Microphone Mode for acoustic guitars (which is why Rocksmith ships a direct-pickup cable and treats microphone input as the asterisked fallback).

The right move

Skip pitch detection entirely. Mount a piezo disc per string at the bridge. Each disc only "hears" its own string because mechanical coupling is local. Feed all 7 piezos into an 8-channel USB audio interface. The browser sees 7 audio channels in parallel. The channel that fires brightest IS the string that was plucked. No pitch detection. No FFT. No autocorrelation. Just per-channel RMS onset detection.

// pseudocode — total software footprint for input detection
const THRESH = 0.02;
const DEBOUNCE_MS = 50;
const lastFireTime = [0,0,0,0,0,0,0];

function processFrame(channelBuffers, t) {
  const rms = channelBuffers.map(buf =>
    Math.sqrt(buf.reduce((s, x) => s + x*x, 0) / buf.length)
  );
  const loudest = rms.indexOf(Math.max(...rms));
  if (rms[loudest] > THRESH && t - lastFireTime[loudest] > DEBOUNCE_MS) {
    lastFireTime[loudest] = t;
    return { string: loudest, time: t };
  }
  return null;
}

▸ CROSSTALK HANDLING

String 4 picks up some signal from string 3 vibrating because they share a soundboard. The fix is the foam pad isolation under each piezo (mechanical) plus the argmax in the code above (logical). Adjacent strings will produce 6-12 dB lower RMS than the actually-plucked string. Picking the loudest channel resolves it cleanly. If crosstalk turns out to be worse than expected, increase the foam thickness or add a 3 dB threshold on margin-of-victory.

Bonus: pressed notes (anyin) become trivial later

For V2, when Bekah does an anyin (pressing a string with the left hand to change its pitch), the piezo on that specific string still fires — we know which string she's pressing without any pitch detection at all. Add a single FFT per channel only after onset, and you get the pressed-note pitch on top. This is the elegance of the per-string approach: it makes the V2 problem an extension, not a rewrite.

05 Game design

7 lanes, falling notes, hit zone at the bottom. Couple of guqin-specific twists.

Visual language — three directions on the table

Three legitimate aesthetic directions, each appropriate for a different audience. Probably ship one base theme and unlock others. The traditional ink-wash direction is the most "this is a guqin app", the cyberpunk direction is the one that goes viral, the fever-mode maximalism direction is what triggers when you're holding a 200+ combo.

▸ FEVER MODE · 200+ COMBO STATE

Note types (MVP → V2)

  • Pluck — single tap. The 95% case.
  • Held tone — plucked then sustained while a "tail" scrolls. Encourages letting strings ring.
  • V2: Slide — pluck string N, slide left hand. Detected via post-pluck pitch drift. Maps to roufa (vibrato) and chuofa (slide-up) techniques.
  • V2: Harmonic — special note, pluck while left hand lightly touches a hui marker. Detect by the doubled-frequency overtone signature.

Scoring

Standard rhythm game timing windows: Perfect (±25ms), Good (±50ms), OK (±100ms), Miss. Combo multiplier ramps to 4x at 30 streak. Wrong-string hits break combo. Skipped notes break combo. End-of-song grade S/A/B/C/F based on accuracy %.

Modes

  • Practice — tempo slider 0.5x–1.0x, no scoring, infinite retries on missed notes
  • Performance — full-speed, scored, no retries
  • Free play — no chart, no scoring, just visualizes what string she's playing in real time (great for ear training and finding strings by sound)

06 Charting & song library

The hardest ongoing problem. Bootstrapping plus authoring.

A rhythm game lives or dies on its song library. Three paths in priority order:

1. Auto-convert from MIDI

Plenty of Chinese folk songs (Mo Li Hua, Liang Zhu, Yangguan San Die) exist as MIDI on archives like ichinesemusic.com and individual collector sites. A Python script reads the melody track, transposes to fit C2–D3, and snaps each note to the nearest of the 7 strings. Output: chart JSON. Bootstraps the library to ~30 songs in a weekend.

# charter.py — uv script with inline deps
# /// script
# dependencies = ["mido", "pydantic"]
# ///
import mido
from pathlib import Path

STRINGS_HZ = [65.41, 73.42, 87.31, 98.00, 110.00, 130.81, 146.83]

def midi_to_string(midi_note: int) -> int | None:
    hz = 440 * 2 ** ((midi_note - 69) / 12)
    cents = [1200 * (hz / s).bit_length() for s in STRINGS_HZ]
    closest = min(range(7), key=lambda i: abs(cents[i]))
    return closest if abs(cents[closest]) < 50 else None

2. Hand-authoring tool

A web-based chart editor: load an MP3, scrub through, click lanes to place notes. Same DOM as the game, just in edit mode. ~1 weekend to build, makes original arrangements possible.

3. Listen-and-learn

V3 stretch goal: she plays a song into the mic, system records the sequence, becomes a chart. Closes the loop completely.

▸ WHY THIS BEATS THE ORIGINAL "JUST USE A MIC" PLAN

The original budget was $120-170 for a USB mic and pitch tracking. We saved on hardware and lost on the actual working game. The piezo plan adds ~$150 in hardware but gives you (1) 5-10ms latency instead of 25-70ms, (2) zero pitch detection failures, (3) inherent immunity to room noise and the dog barking, (4) a clean V2 path for pressed notes. Hardware cost is a one-time tax. Detection failure is a permanent tax on every play session.

08 Phased build plan

Each phase is independently shippable and provides value alone.

Phase 0 — Spike

Validate the piezo rig
~3 hours after parts arrive · No game logic
  • Mount all 7 piezos under the bridge with foam pads + painter's tape
  • Wire each to its UMC1820 channel, set channels to instrument-Hi-Z
  • Web page reads aggregate device, displays per-channel RMS bars in real time
  • Bekah plucks each string. Verify the right channel lights up, others stay quiet
  • Measure crosstalk: when she plucks string 4, what's the amplitude on strings 3 and 5?
  • Pass criterion: plucked string is >6 dB louder than any neighbor on every plunk
  • Failure mode: if crosstalk is too high, swap to thicker foam or move piezos closer to bridge

10 Decisions you need to make

Pick before code starts.

Q1
Web app or native (Godot)? Web is faster to ship, easier to update, casts to TV trivially. Godot wins on latency and would slot into your existing duct-cleaning-sim ambitions. Recommendation: web for MVP, port to Godot only if you decide to ship on Steam.
Q2
UMC1820 used or new? Used saves ~$80, hardware is identical, drivers and warranty don't matter for our use case (it's class-compliant on Mac). New comes from Sweetwater with a return window if it shows up DOA. Recommendation: used from Reverb if you can wait 5-7 days for shipping. New from Sweetwater if you want it tomorrow.
Q3
First song? Mo Li Hua is the safe, recognizable, mostly-open-string pick. Chun Jiang Hua Yue Ye is a real guqin standard but harder. Tetris theme is funny but will trigger arguments about whether this is a serious project. Recommendation: Mo Li Hua. BIAR will weigh in.
Q4
Default visual theme? Ink-wash (Theme A) is the most "this is a guqin app", appropriate, period-correct. Cyberpunk (Theme B) is louder and more video-game-y. The fever-mode maximalism is a unlockable state, not a default. Recommendation: Ink-wash default, cyberpunk skin unlocked at Phase 2.
