The Infrastructure

Actual Screenshots From Building This

GitHub Repository

Claude pushes files directly via the GitHub API. No git CLI, no IDE, no manual anything. Just REST calls with base64-encoded HTML.

The repo is connected to Cloudflare Pages. Commit lands, deployment starts, ~10 seconds later it's live on the CDN.

  • Each artifact gets its own folder
  • Commits show Claude as the author
  • Public repo, anyone can see the code
The claude-artifacts repo — "Artifacts deployed by Claude"

Cloudflare Worker

The middleware that makes it all work. Claude's sandbox has weird TLS issues, so the worker acts as a trusted proxy to Cloudflare's own services.

R2 for storing images. D1 for database queries. All exposed as dead-simple POST endpoints with bearer token auth.

  • POST /upload → Images to R2
  • GET /r2/file/* → Serve publicly
  • POST /d1/query → SQLite queries
Worker bindings: D1_DB for the database, R2_BUCKET for storage

Build Your Own

How to Set This Up

1. Cloudflare Worker

Build a proxy with endpoints for R2 uploads, D1 queries, whatever else you need. Add bearer token auth. Deploy to workers.dev.

2. GitHub + Pages

Create a repo. Connect it to Cloudflare Pages with no build command. Now any commit auto-deploys as a static site.

3. Save to Memory

Tell Claude to remember the tokens, URLs, and workflows. They persist across all sessions. You never set it up again.

4. Define Intent

Add memory notes for disambiguation. "Deploy" = Cloudflare. "Artifact" = Claude UI. Now Claude knows what you mean.
