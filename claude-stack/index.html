The Infrastructure

What's Actually Running

GitHub Repository

Claude pushes HTML files directly to a GitHub repo using the GitHub API. No git CLI needed—just a REST call with base64-encoded content.

The repo is connected to Cloudflare Pages, so any commit triggers an automatic deployment. Zero configuration required.

  • Public repo for artifacts
  • Each artifact gets its own folder
  • Commits show as "Add [artifact name]"
The claude-artifacts repo on GitHub, showing commits made by Claude

Cloudflare Worker

A middleware proxy that gives Claude access to Cloudflare services. It handles authentication, bypasses sandbox TLS restrictions, and exposes simple endpoints.

The worker connects to R2 (object storage) for images and D1 (SQLite database) for persistent data—all accessible via simple POST requests.

  • POST /upload → Store files in R2
  • GET /r2/file/* → Serve files publicly
  • POST /d1/query → Query the database
Cloudflare dashboard showing the worker's resource bindings: D1 database and R2 storage

How to Build This Yourself

The Setup (One-Time)

1. Create a Cloudflare Worker

Build a simple proxy that handles R2 uploads, D1 queries, and any other APIs you need. Add bearer token auth so only Claude can use it.

2. Connect GitHub to Pages

Create a repo for artifacts. Connect it to Cloudflare Pages with no build command—it just serves static files from the repo root.

3. Save Tokens to Memory

Tell Claude to remember the worker URL, auth key, GitHub token, and repo name. These persist across all future sessions.

4. Define the Workflow

Add a memory note explaining when to use artifacts vs. deploy. Now Claude knows your intent from context.
