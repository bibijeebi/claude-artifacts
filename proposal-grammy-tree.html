Proposal #040

Grammy's Tree, Relit

Grammy is giving us her Balsam Hill tree. The tree is premium, the factory lights are junk. Strip them, relight it with the WS2811 bullet pixels already sitting in garbage bags in the garage, and run it off WLED. Warm white the second it's plugged in, anything else from a phone.

Cost$25–90
Difficulty2/5, mostly tedium
TimeOne weekend
CategoryHome

Bottom Line

A free premium tree plus pixels, power supplies, ESP32s and project boxes we already own means the only real cost is one weekend of snipping. New spend is connectors, ties and wire, $25–40. Spending more only buys convenience (a ready-made WLED controller, a fresh power supply). The result beats any store pre-lit tree, because nothing in it is proprietary and every bulb is replaceable.

Concept render, not the actual tree. Target look: warm white, pixels pushed deep into the branches, controller hidden on the skirt.

How It's Wired

One pixel run per tree section, joined at each section seam with a 3-pin pigtail so the tree still comes apart for storage. Power gets re-injected at every seam, which is where the run breaks anyway.

Pixel count depends on the tree. Balsam Hill doesn't publish one per-foot rule, so count after pickup. The working target is roughly the factory bulb count in pixels or a bit under, since pixels are brighter than mini lights. For a 7.5 ft tree that's ballpark 8–12 strings of 50.

Power Math

A 12V, 50-count, 4″-spacing bullet string is rated 15 W, 1.25 A per string (Light-O-Rama spec), about 0.025 A per pixel at full white. Generic bullets run close to that.

Set WLED's automatic brightness limiter (LED settings) to the supply's real amp rating minus 15%. Then even a full-white accident can't overload anything. A tree never runs full white anyway; it looks like a stadium.

The Build, Start To Finish

Eight phases. Phases 1–3 happen at the bench and can start before the tree even shows up. The order matters: every string gets tested before it touches a branch, because finding a dead pixel buried in a woven tree costs an hour, and finding it on the bench costs a minute.

Phase 0: Before pickup30 min
  1. Clear a storage spot for 11 months of the year. Measure it against the box once you see the box.
  2. Pull every bag of bullet pixels out and count strings. Note the connector type on the ends (usually 3-pin JST-SM) and buy matching pigtails.
  3. Pick a 12V supply that covers the pixel count (see Power Math). Use an enclosed supply or put the screw terminals in a project box. Bare mains terminals don't go under a tree skirt.
  4. Order the shopping list so it lands before pickup weekend.
Phase 1: Flash the controller20 min
  1. Plug an ESP32 into the Mac over USB. Open install.wled.me in Chrome (Web Serial doesn't work in Safari) and hit Install.
  2. When it asks, give it the home Wi-Fi. If you skip that, it broadcasts its own WLED-AP network you can join from the phone to finish setup.
  3. Open its IP in a browser. Under Config → WiFi Setup, set the mDNS name to tree so it's always at http://tree.local.
  4. Under Config → LED Preferences, set the output type to WS281x and the data GPIO to whatever pin you wire. GPIO 16 is a clean choice on a plain ESP32 dev board.
Phase 2: Bench-test every string1–2 hrs

Build the controller first, then run every string through it one at a time before anything goes on the tree.

  1. Wire the box: 12V from the supply through the inline fuse to the string's power, 12V to the buck converter, and the buck's 5V to the ESP32's 5V/VIN pin. Put a 220–470Ω resistor in series on the data line right at the ESP32 pin, and tie the ESP32 ground to the 12V supply ground. A shared ground is mandatory. Without it, data is garbage.
  2. Identify wires with a multimeter, not by color. Generic bullets vary. Usually red is +12V, white or blue is ground, green is data. The little arrows on the pixel housings point in the direction of data flow, so the controller feeds the arrow's tail end.
  3. Set LED count to 50 and pick Solid white at low brightness. Every pixel lights or it doesn't.
  4. If the colors come out wrong (you pick red and get green), change Color order in LED Preferences. WLED defaults to GRB, and many 12V bullets are RGB.
  5. Run a chase effect. A string that dies partway means the last lit pixel or the first dark one is bad. Cut it out and splice the neighbors with solder and heat shrink.
  6. Tag each tested string with tape. Set aside one partial string as repair spares.
Phase 3: Strip the factory lights2–4 hrs
  1. Set the tree up fully once and take phone photos of each section. These are your reference for how the branches fold.
  2. Count the factory bulbs on one section and multiply by the section count. That's the pixel target, or a bit under.
  3. Work one section at a time. Factory strings are clipped or twisted onto the branches. Snip the wire near each clip with flush cutters and pull the strand free.
  4. Leave the trunk wiring and the plugs inside the pole alone, dead in place. Pulling them can crack the pole or loosen the branch hinges.
  5. Pick out the leftover clips. Any plastic left behind snags the new pixels.
Phase 4: Weave the pixels3–5 hrs
  1. Start with the bottom section, and start the run at the trunk next to the controller box.
  2. Go branch by branch. Run out along the top of each main branch to about 2″ from the tip, then back along the underside to the trunk, and step to the next branch. Pixels deep inside the tree give it depth. Pixels only on the tips look like a lit cone.
  3. Turn each bullet so it points out, not down. Fix the wire with green twist ties or floral wire at every few pixels. Don't use zip ties. They pinch, and you can't adjust them.
  4. Keep spacing even. Step back every few branches and squint. Dark holes and bright clumps show up best with the room lights off and the pixels on.
  5. Finish each section's run at the trunk, right below the top of the pole, and end it in a pigtail half. The next section starts with the matching half.
  6. Write down the pixel count per section, for example bottom 220, middle 180, top 100. You need these numbers for segments and for repairs.
Phase 5: Power injection1 hr
  1. Run 18 AWG red/black up the trunk from the supply to each seam. Inject both +12V and ground at the start of every section, at the same pigtail as the data.
  2. Use the 3-pin pigtail for data and power through the seam, plus a separate 2-pin pigtail for each injection pair. Every seam pulls apart with nothing to unscrew.
  3. Run everything off one supply. If you ever use two, tie the grounds together and never the +12V outputs.
  4. Check voltage at the top section with the tree at full white for a few seconds. Anything above about 11V is fine. Lower than that, or a warm, pinkish tint toward the top, means you need another injection point.
  5. Tape the injection wire to the pole on the side toward the wall.
Phase 6: Configure WLED30 min
  1. LED Preferences: set the total pixel count. Leave Enable automatic brightness limiter on. Set Maximum PSU Current to the supply's rating minus 15%. Set mA/LED to Custom, 25 mA, since the default 55 mA is meant for 5V strip.
  2. Segments: make one segment per tree section using your per-section counts. Effects can then run per section, or you can turn off just the top for a topper.
  3. Presets: save four. Warm White is Solid with the white set around 2700K, at about 40% brightness. Candle is the Candle Multi effect. Twinkle is TwinkleFOX on a warm palette. Multicolor is a slow twinkle on a multicolor palette. Name them in plain English. Bekah or a guest should never have to touch an effect slider.
  4. Set Apply preset at boot to the Warm White preset number and leave Turn LEDs on after power up/reset on. Now it acts like any tree: plug it in and it's on, warm white.
  5. Time & Macros: add a schedule if you want it automatic, for example on at sunset and off at 11pm.
  6. Install the WLED app on both phones. If you want "Alexa, turn on the tree," enable Alexa under Sync Interfaces.
  7. Back up the config and presets (Config → Security & Updates, backup buttons). Save the files with this proposal so a dead ESP32 is a 10-minute swap.
Phase 7: Prove it, then put it away1 hr
  1. Run it 4+ hours on Warm White. Feel the supply, the box and each seam. Warm is fine. Hot means a bad joint or an undersized wire.
  2. Take it fully apart and put it back together once. All three sections should light on the first try.
  3. Label each seam (A/B) on both pigtail halves with a paint pen.
  4. Leave the pixels on the branches for storage. Fold the branches up per the original box, coil the injection lead and pigtails at the top of each pole section, and store the controller and supply in a labeled bag with a spare fuse.

Troubleshooting

SymptomCauseFix
Nothing lightsData fed at the wrong end, wrong GPIO, or no shared groundCheck the arrows, the GPIO setting and the ground tie
Everything past one point is dark or randomDead pixel or a bad seam pigtailReseat the seam first, then cut out the first dark pixel and splice
Colors are wrong everywhereColor orderTry RGB in LED Preferences
First pixel flickers3.3V data is marginalShorten the data lead, add the 74AHCT125, or sacrifice the first pixel as a booster
Top section is dim or pink at full whiteVoltage dropAdd an injection point, or let the brightness limiter handle it
Random resets or flashesThe ESP32's supply is saggingCheck the buck converter output and add a 1000µF cap across the 12V at the box
