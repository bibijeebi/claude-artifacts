The mental model

Hub-resident vs phone-resident

The Home app and the Shortcuts Automation tab are two windows onto the same database. Everything you build is one of these two things. Get this distinction and the rest is detail.

🏠

Home automation

stored on Apple TV / HomePod
  • ✓Runs for everyone in the home, not just you
  • ✓Keeps working when your phone's away or dead
  • ✓Exactly 5 HomeKit triggers, nothing else
  • ✓No logic by default. Run a scene, set accessories, auto-revert
  • ✓Shareable, since it lives in the home
📱

Personal automation

stored on one iPhone
  • ✓Runs only for you, never fires for Bekah's phone
  • ✓Needs that phone present, some triggers prompt first
  • ✓Phone-side triggers: NFC, Focus, Wi-Fi, time, app…
  • ✓Full Shortcuts logic from the start
  • ✓Can call Home actions, becoming a trigger HomeKit lacks
Home automation

The only 5 triggers

Every hub-resident automation starts with one of these. The first three are about people and time. The last two react to your accessories.

Time

A Time of Day Occurs

Sunrise, sunset, or a clock time. Can gate on day-of-week and on who's home.

People

People Arrive

Anyone, the first person, or a specific person reaches a location.

People

People Leave

Same options. "Last person leaves" is the canonical everyone's-gone trigger.

Accessory

An Accessory is Controlled

A light turns on, a lock unlocks, the garage opens. Chain one device to others.

Sensor

A Sensor Detects Something

Motion, contact, occupancy, leak, smoke. The reactive workhorse.

The native action set is thin on purpose: run a scene, set accessories to states, or auto-revert after X minutes ("turn off after 1 hour"). No conditionals. No reading a sensor's value. That ceiling is exactly what the next section removes.
The relationship to Shortcuts

One button changes everything

Build a Home automation, pick a trigger, then on the accessories screen swipe up and tap Convert To Shortcut. It still lives on the hub and still runs for everyone, but now the full Shortcuts library is inside it. Flip the switch to see what you gain.

Personal automation

Phone-side triggers

These never existed in HomeKit. Your phone's own state becomes the trigger, and the automation can then call Home actions to fire a scene or toggle a device. Tap an NFC tag, run a HomeKit scene.

🕐Time of Day ⏰Alarm 📍Arrive / Leave 📳NFC tag 🌙Focus / Sleep 📶Wi-Fi connect 🔵Bluetooth 🚗CarPlay 📲App opened / closed 🔋Battery level 🔌Charger 🪫Low Power Mode ✈️Airplane Mode ✉️Message / Email
Run-silently caveat: NFC and Focus run without a prompt. As of iOS 26, Wi-Fi and Bluetooth triggers run silently too (marked 26 above). Location and some others may still ask before running. A personal automation can't be shared, so once you script multiple devices it lives on that one phone.

What iOS 26 changed

New since the last release

If you skipped the upgrade notes, here's what actually matters for automations.

Required

New HomeKit architecture

The old one was retired in fall 2025. The upgrade unlocks guest access, robot vacuums, and Activity History.

Native

Adaptive Temperature

Built-in thermostat automation. On-device prediction pre-conditions a Matter thermostat for arrival, sleep, and away. No building required.

Silent

Wi-Fi & Bluetooth run silently

Personal automations on these triggers can finally fire without an "Ask Before Running" prompt.

Parity

Sleep Focus on/off triggers

Sleep Focus now has explicit turn-on and turn-off triggers, matching every other Focus. Clean goodnight routines at last.

Smarter

25+ new actions + Use Model

New Shortcuts actions plus LLM "Use Model" steps (Apple Intelligence / ChatGPT) you can drop straight into a converted automation.

Mac

Personal automations on macOS

macOS 26 gets personal automations for the first time, so your Mac can join the trigger party.

For the whole-house build

HomeKit is the voice. HA is the brain.

When you outgrow what HomeKit exposes, keep the Apple side dumb and offload logic to Home Assistant. A converted automation (or any shortcut) fires a webhook; HA does the thinking; the result mirrors back into the Home app so Siri stays in sync.

✕ Self-state loop

A HomeKit automation can't read a device's own state to control itself. The smart-plug-can't-re-toggle-itself problem. HA handles it natively.

✕ Value thresholds & AND/OR

The Home app won't expose numeric sensor thresholds or multi-sensor AND/OR conditions. HA fuses as many sensors as you want.

Don't want HA? The Eve app and Controller for HomeKit expose more of the underlying HomeKit trigger API than Apple's Home app does, including sensor-value thresholds and Thread network status. Good middle ground before going full Home Assistant.
