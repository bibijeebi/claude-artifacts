PHASE 1

System Literacy

Before you write code, you need to be comfortable in the machine. This is the difference between "I can follow a tutorial" and "I can figure things out."

Filesystem Navigation & Manipulation

# Where am I, what's here
ls | sort-by size -r
ls **/* | where type == file | sort-by size -r | first 20

# Finding things
fd "*.log"
fd -e py -e js
rg "password" .
rg -l "TODO" --type py

# Bulk rename
ls *.jpg | each { |f| mv $f.name $"photos/($f.name)" }

# Disk usage by subdirectory
ls | where type == dir | each { |d|
  { name: $d.name, size: (du $d.name | get apparent | first) }
}
The exercise: Pick a messy folder (Downloads, Desktop, whatever). Organize it entirely from Nu. Rename, sort, deduplicate, move. Don't touch the GUI.

Process & System Awareness

ps | sort-by cpu -r | first 10
ps | where name =~ "chrome" | get mem | math sum
$env.PATH | split row (char esep)

# Data format conversion (Nu eats everything)
open data.csv | where age > 30 | to json | save filtered.json
http get https://jsonplaceholder.typicode.com/users | select name email

PowerShell: Read Literacy Only

You won't use it daily, but you need to read it. Every Windows tutorial and sysadmin script is written in it.

# Cmdlets: Verb-Noun pattern
Get-Process          # = ps in Nu
Get-ChildItem        # = ls
Get-Content          # = open (text)
Where-Object         # = where

# $_ is "current item" (like $in in Nu)
Get-Process | Where-Object { $_.CPU -gt 10 }

# COM objects = Windows app automation
$excel = New-Object -ComObject Excel.Application
$wscript = New-Object -ComObject WScript.Shell

# WMI/CIM = system info database
Get-CimInstance Win32_Processor
Get-CimInstance Win32_LogicalDisk

# .NET access (PS is a .NET shell)
[System.IO.File]::ReadAllText("file.txt")
[Math]::Sqrt(144)
The mental model: PowerShell is a .NET REPL that happens to be a shell. COM objects let you automate Windows apps. WMI/CIM is a system-info database. The Registry is a giant config file. You don't memorize this, you recognize it and know what to Google.
PHASE 2

AI-Assisted Shell Work

This is the game-changer. AI in the terminal isn't a gimmick, it's a fundamentally different way to work and learn.

Claude Code

The most powerful option. It reads files, runs commands, edits code, and chains operations autonomously.

# Just talk to it
claude "find all Python files that import requests and list them"
claude "explain what this PowerShell script does"
claude "write a script that monitors this folder for new CSVs"

# Interactive mode for longer sessions
claude

# Pipe data in
cat weird_log.txt | claude "parse this and extract all errors"

Claude Code isn't autocomplete. It's a pair programmer that can do things on the system. Use it to explore codebases, debug failures, automate tasks, and learn interactively.

aichat (sigoden/aichat)

Lighter weight. Quick questions and piping data through AI.

aichat "what does the -R flag do in chmod"

cat error.log | aichat "summarize these errors"

# Generate shell commands
aichat -r shell "find files modified today larger than 10MB"

# Generate code
aichat -r code "python: CSV path to summary dict"

The AI-Assisted Learning Loop

  1. Encounter something you don't understand. A script, config file, error, or concept.
  2. Ask AI in the terminal. Don't context-switch to a browser.
  3. Try it immediately. AI explains sockets? Open a Python REPL and make one.
  4. Break it on purpose. Change things, see errors, ask AI to explain them.
  5. Build something small with it. Even 10 lines. Commit it.

Build Your Own AI Shell Tools

#!/usr/bin/env -S uv run --with httpx,anthropic
"""Pipe anything to this and get a summary."""
import sys, anthropic

text = sys.stdin.read()
msg = anthropic.Anthropic().messages.create(
    model="claude-sonnet-4-20250514",
    max_tokens=1024,
    messages=[{"role": "user",
               "content": f"Summarize concisely:\n\n{text}"}]
)
print(msg.content[0].text)

Save as summarize.py. Now: cat giant_report.txt | python summarize.py. You just built your first AI tool. From here: commit message generators, code reviewers, log analyzers, documentation writers.

Python (The Main Event)

Stage 1: Interactive Exploration (Week 1-2)

Don't write files yet. Use IPython or uvx one-shots. The goal is muscle memory.

# Strings (you'll use these constantly)
path = "/home/user/documents/report_final_v2.txt"

# Core data structures (95% of everything)
nums = [3, 1, 4, 1, 5, 9, 2, 6]
sorted(nums)                                # [1, 1, 2, 3, 4, 5, 6, 9]
set(nums)                                   # {1, 2, 3, 4, 5, 6, 9}
[x**2 for x in nums if x > 3]               # list comprehension
{x: x**2 for x in range(5)}                # dict comprehension

# pathlib (always use this, never os.path)
from pathlib import Path
list(Path(".").glob("**/*.py"))              # recursive find
(Path("data") / "results.csv").read_text()   # path joining
Week 1 exercise: Open IPython. Use only pathlib and built-in types to explore your filesystem. List, read, count, find the biggest files, find duplicates. No scripts, just REPL.

PHASE 4

Math from the Terminal

Not a prerequisite, but a force multiplier. Python makes math tangible and interactive.

from sympy import *
x = Symbol('x')

solve(x**2 - 5*x + 6, x)                # [2, 3]
diff(sin(x) * exp(x), x)                 # derivative
integrate(1/(1 + x**2), x)               # arctan(x)
series(exp(x), x, 0, 6)                  # Taylor series

# Linear algebra
import numpy as np
A = np.array([[1,2],[3,4]])
np.linalg.eigvals(A)                      # eigenvalues

# Learn probability by simulation
import random
wins = sum(random.choice([0,1,2]) != random.choice([0,1,2])
           for _ in range(100_000))
print(f"Monty Hall switch wins {wins/1000:.1f}%")  # ~66.7%
Where to practice: Project Euler (projecteuler.net). Bite-sized math+code puzzles, hundreds of them, escalating difficulty. Problem 1 takes 5 minutes. Problem 50 takes an hour. Perfect for work downtime.
